    49→# Capítulo 3 — Integração com ERPs
    50→
    51→## 3.1 Totvs (Protheus e RM)
    52→
    53→### Visão
    54→Sincroniza dados de vendas do Totvs com o Orion para lançar resultados automaticamente.
    55→
    56→### Autenticação
    57→- OAuth 2.0 com client credentials
    58→- Ou Basic Auth com API key (legado)
    59→
    60→### Endpoints Consumidos (Totvs → Orion)
    61→```
    62→GET /api/v1/sales?date={YYYY-MM-DD}
    63→GET /api/v1/sales/{id}/items
    64→GET /api/v1/products/{id}
    65→GET /api/v1/sellers/{id}
    66→```
    67→
    68→### Mapeamento de Dados
    69→
    70→| Totvs Field | Orion Field | Transformação |
    71→|-------------|-------------|---------------|
    72→| `F2_EMISSAO` | `result_date` | Date parse |
    73→| `F2_VEND1` | `user.external_id` | Lookup por CPF |
    74→| `F2_VALBRUT` | `value` | Decimal(18,4) |
    75→| `F2_DOC` + `F2_SERIE` | `external_reference` | Concatenação |
    76→| `C6_PRODUTO` | `product.external_id` | Lookup |
    77→| `C6_VALOR` | `sale_item.value` | Decimal |
    78→
    79→### Fluxo
    80→```
    81→1. Scheduler roda a cada 30min (configurável)
    82→2. Busca vendas no Totvs desde última sincronização
    83→3. Para cada venda:
    84→   - Identifica vendedor por CPF
    85→   - Mapeia indicadores (configurável: faturamento, itens, etc.)
    86→   - Lança resultado no Orion via API
    87→4. Marca timestamp de última sync
    88→5. Emite evento result.imported (auditado)
    89→```
    90→
    91→### Tratamento de Erros
    92→- Vendedor não encontrado: cria log, pula registro
    93→- Valor inválido: cria log, pula registro
    94→- Timeout Totvs: retry 3x com backoff exponencial
    95→
    96→### Configuração no Orion
    97→```
    98→Admin > Integrações > ERP > Totvs
    99→- URL base: https://api.totvs.com.br
   100→- Client ID: ****
   101→- Client Secret: ****
   102→- Empresa: 01
   103→- Filial: 0101
   104→- Sincronizar a cada: 30 min
   105→- Indicador padrão: Faturamento
   106→- Status: Ativo
   107→```

   607→## 12.2 Payload Padrão
   608→
   609→```json
   610→{

   614→  "data": {
   615→    "goalId": 42,
   616→    "userId": 10,
   617→    "userName": "João Silva",
   618→    "indicatorId": 3,
   619→    "indicatorName": "Faturamento",
   620→    "achievementPercent": 110.5,
   621→    "targetValue": 30000,
   622→    "achievedValue": 33150
   623→  },
   624→  "signature": "sha256=abc123def456..."
   625→}

   627→
   628→## 12.3 Assinatura HMAC
   629→
   630→Todo webhook é assinado. Header:
   631→```
   632→X-Orion-Signature: sha256=<hmac>
   633→X-Orion-Event: goal.achieved
   634→X-Orion-Delivery: <uuid>
   635→```
   636→
   637→Cliente valida:
   638→```python
   639→import hmac, hashlib
   640→
   641→def verify_signature(payload, signature, secret):
   642→    expected = 'sha256=' + hmac.new(
   643→        secret.encode(),
   644→        payload.encode(),
   645→        hashlib.sha256
   646→    ).hexdigest()
   647→    return hmac.compare_digest(expected, signature)
   648→```
   649→
   650→## 12.4 Retry Policy
   651→
   652→- 3 tentativas com backoff exponencial: 1min, 5min, 30min
   653→- Após 3 falhas: webhook desativado
   654→- Cliente é notificado por e-mail
   655→- Pode reativar manualmente
   656→

   924→### Regras de Transformação
   925→1. **CPF/CNPJ:** Remove formatação (`.` e `-`), mantém apenas dígitos
   926→2. **Datas:** `DD/MM/YY` → `YYYY-MM-DD` (ISO 8601)
   927→3. **Decimais:** Totvs usa `,` como separador decimal, Orion usa `.`
   928→4. **Char para Number:** Strip leading zeros (`"00042"` → `42`)
   929→5. **Lookup de vendedor:** `F2_VEND1` (código Protheus) → buscar `users.external_id` no Orion
   930→6. **Multi-tenant:** Sempre filtrar por `F2_FILIAL` correspondente ao tenant

  1698→## 17.2 Implementação no Orion
  1699→
  1700→### Token Bucket Algorithm
  1701→```typescript
  1702→class TokenBucket {
  1703→  private tokens: number;
  1704→  private lastRefill: number;
  1705→  
  1706→  constructor(
  1707→    private capacity: number,
  1708→    private refillRate: number,  // tokens per second
  1709→  ) {
  1710→    this.tokens = capacity;
  1711→    this.lastRefill = Date.now();
  1712→  }
  1713→  
  1714→  async consume(count: number = 1): Promise<boolean> {
  1715→    const now = Date.now();
  1716→    const elapsed = (now - this.lastRefill) / 1000;
  1717→    this.tokens = Math.min(this.capacity, this.tokens + elapsed * this.refillRate);
  1718→    this.lastRefill = now;
  1719→    
  1720→    if (this.tokens >= count) {
  1721→      this.tokens -= count;
  1722→      return true;
  1723→    }
  1724→    return false;
  1725→  }
  1726→  
  1727→  async waitForToken(): Promise<void> {
  1728→    while (!(await this.consume(1))) {
  1729→      await sleep(100);
  1730→    }
  1731→  }
  1732→}
  1733→
  1734→// Por provedor
  1735→const rateLimiters = {
  1736→  totvs: new TokenBucket(100, 100/60),  // 100/min
  1737→  sap: new TokenBucket(60, 1),          // 60/min
  1738→  sankhya: new TokenBucket(30, 0.5),    // 30/min
  1739→  whatsapp: new TokenBucket(80, 80/3600),// 80/hora
  1740→  // ...
  1741→};
  1742→```

  1758→### Circuit Breaker
  1759→Após N falhas consecutivas, circuito abre e paramos de tentar:
  1760→```typescript
  1761→class CircuitBreaker {
  1762→  private failures = 0;
  1763→  private lastFailure = 0;
  1764→  private state: 'closed' | 'open' | 'half-open' = 'closed';
  1765→  
  1766→  constructor(
  1767→    private threshold: number = 5,
  1768→    private resetTimeout: number = 60_000,
  1769→  ) {}
  1770→  
  1771→  async execute<T>(fn: () => Promise<T>): Promise<T> {
  1772→    if (this.state === 'open') {
  1773→      if (Date.now() - this.lastFailure > this.resetTimeout) {
  1774→        this.state = 'half-open';
  1775→      } else {
  1776→        throw new Error('Circuit breaker open');
  1777→      }
  1778→    }
  1779→    
  1780→    try {
  1781→      const result = await fn();
  1782→      this.failures = 0;
  1783→      this.state = 'closed';
  1784→      return result;
  1785→    } catch (e) {
  1786→      this.failures++;
  1787→      this.lastFailure = Date.now();
  1788→      if (this.failures >= this.threshold) {
  1789→        this.state = 'open';
  1790→      }
  1791→      throw e;
  1792→    }
  1793→  }
  1794→}
  1795→```

  1797→## 17.3 Rate Limit por Cliente Orion
  1798→Além do limite do provedor externo, Orion impõe limites por cliente (para evitar abuso):
  1799→- 1000 API calls/hora por cliente (plano Starter)
  1800→- 5000 API calls/hora (Professional)
  1801→- 50000 API calls/hora (Enterprise)
  1802→
  1803→Implementado via Redis com sliding window:
  1804→```typescript
  1805→async function checkRateLimit(tenantId: number, plan: string): Promise<boolean> {
  1806→  const limits = { starter: 1000, professional: 5000, enterprise: 50000 };
  1807→  const limit = limits[plan] || 1000;
  1808→  const key = `ratelimit:${tenantId}:${Math.floor(Date.now() / 3600000)}`;
  1809→  const count = await redis.incr(key);
  1810→  if (count === 1) await redis.expire(key, 3600);
  1811→  return count <= limit;
  1812→}
  1813→```

  1817→# Capítulo 18 — Error Handling por Integração
  1818→
  1819→## 18.1 Categorias de Erro
  1820→
  1821→### Erros de Conexão (Network)
  1822→- DNS falhou
  1823→- TCP timeout
  1824→- TLS handshake falhou
  1825→- Connection refused
  1826→
  1827→### Erros de Autenticação (Auth)
  1828→- 401 Unauthorized (token expirado ou inválido)
  1829→- 403 Forbidden (sem permissão)
  1830→- Token malformado
  1831→
  1832→### Erros de Cliente (4xx)
  1833→- 400 Bad Request (payload inválido)
  1834→- 404 Not Found (recurso não existe)
  1835→- 409 Conflict (já existe)
  1836→- 422 Unprocessable Entity (validação semântica)
  1837→- 429 Too Many Requests (rate limit excedido)
  1838→
  1839→### Erros de Servidor (5xx)
  1840→- 500 Internal Server Error (erro genérico)
  1841→- 502 Bad Gateway
  1842→- 503 Service Unavailable
  1843→- 504 Gateway Timeout
  1844→
  1845→### Erros de Aplicação (Negócio)
  1846→- Vendedor não encontrado no Orion
  1847→- Valor inválido (negativo, não-numérico)
  1848→- Data fora de período permitido
  1849→- Empresa não autorizada para integração
  1850→
  1851→## 18.2 Estratégia por Tipo de Erro
  1852→
  1853→| Tipo | Ação | Retry? | Notifica? |
  1854→|------|------|--------|-----------|
  1855→| Connection (timeout) | Log + retry | Sim (3x backoff exp) | Após 3 falhas |
  1856→| Auth (401) | Não tentar de novo | Não | Sim, imediato (token pode ter expirado) |
  1857→| Auth (403) | Não tentar de novo | Não | Sim, imediato |
  1858→| 400 | Log detalhado | Não | Não |
  1859→| 404 | Log | Não | Não |
  1860→| 409 | Log (já processado) | Não | Não |
  1861→| 422 | Log | Não | Sim (erro de dado) |
  1862→| 429 | Backoff + retry | Sim (até 5x) | Após 5 retries |
  1863→| 5xx | Retry | Sim (3x backoff exp) | Após 3 falhas |
  1864→| Negócio (vendedor não encontrado) | Log + pular | Não | Sim (resumo no fim) |

  1899→## 18.4 Dead Letter Queue (DLQ)
  1900→Mensagens que falham após todos os retries vão para DLQ:
  1901→- Stored no PostgreSQL em `integration_failures` table
  1902→- Disponível para reprocessamento manual
  1903→- Limpeza após 30 dias
  1904→
  1905→```sql
  1906→CREATE TABLE integration_failures (
  1907→  id BIGSERIAL PRIMARY KEY,
  1908→  tenant_id INT NOT NULL,
  1909→  integration VARCHAR(50) NOT NULL,
  1910→  operation VARCHAR(100) NOT NULL,
  1911→  payload JSONB NOT NULL,
  1912→  error JSONB NOT NULL,
  1913→  attempts INT NOT NULL,
  1914→  last_attempt_at TIMESTAMPTZ,
  1915→  created_at TIMESTAMPTZ DEFAULT NOW(),
  1916→  resolved_at TIMESTAMPTZ,
  1917→  resolved_by INT
  1918→);
  1919→
  1920→CREATE INDEX idx_failures_unresolved ON integration_failures(tenant_id, integration)
  1921→  WHERE resolved_at IS NULL;
  1922→```

  1924→## 18.5 Tratamento Específico por Integração
  1925→
  1926→### Totvs Protheus
  1927→- Token expira em 1 hora → refresh automático
  1928→- Schema XML varia por versão → versionar parser
  1929→- Campos customizados (X2_CAMPO) → ignora se não mapeado
  1930→
  1931→### SAP B1 Service Layer
  1932→- Session timeout 30 min → re-login automático
  1933→- CSRF token em POST → captura e reutiliza
  1934→- $expand com limite 100 → pagina manualmente
  1935→
  1936→### Sankhya
  1937→- XML SOAP body → parser específico
  1938→- XML response aninhado → extract correto
  1939→- Timeouts frequentes em queries grandes → batch menor
  1940→
