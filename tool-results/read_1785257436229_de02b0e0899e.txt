   390→### Fix: Dashboard não clicável + menu inacessível
   391→
   392→**Sintomas reportados pelo usuário:**
   393→- Elementos do dashboard não clicáveis
   394→- Menu não acessível
   395→
   396→**Investigação:**
   397→
   398→1. Verifiquei o HTML renderizado de `/dashboard` — sidebar presente, mas...
   399→2. Inspecionei `public/sw.js` — **causa raiz encontrada**:
   400→   ```js
   401→   // SW ANTIGO (problemático):
   402→   self.addEventListener('fetch', (event) => {
   403→     event.respondWith(caches.match(event.request)
   404→       .then((response) => response || fetch(event.request)));
   405→   });
   406→   ```
   407→   Estratégia **cache-first para TODAS as requisições** (HTML, JS, CSS, API).
   408→   Resultado: navegador servia HTML/JS antigos do cache mesmo após novo
   409→   deploy. Os chunks JS referenciados pelo HTML antigo não existiam mais
   410→   (porque Vercel gera hashes novos a cada build) → 404 → React não
   411→   hidratava → página renderizava estática sem interatividade.
   412→
   413→3. Verifiquei `src/components/ServiceWorkerRegister.tsx` — **componente
   414→   definido mas nunca importado em nenhum layout**. SW antigo continuava
   415→   ativo indefinidamente.
   416→
   417→4. Verifiquei `src/components/Header.tsx` — botão hamburger do menu
   418→   mobile não tinha `onClick={onOpenMobile}` (erro silencioso, sem efeito).
   419→
   420→**Correções aplicadas:**
   421→
   422→1. **`public/sw.js` reescrito** com estratégia híbrida:
   423→   - Navegações HTML: **network-first** (fallback cache offline)
   424→   - Assets estáticos (`_next/static/*`, imagens, fontes): **cache-first**
   425→     (são content-hashed, sempre válidos)
   426→   - API routes: **nunca cachear** (sempre network)
   427→   - Bump `CACHE_VERSION` para `orion-v2-2026-07-27`
   428→   - Activate handler limpa caches antigos automaticamente
   429→   - `self.skipWaiting()` + `clients.claim()` para ativação imediata
   430→
   431→2. **`src/components/ServiceWorkerRegister.tsx`** reescrito:
   432→   - Escuta `updatefound` → `statechange` → `installed`
   433→   - Quando novo SW instala, envia `SKIP_WAITING`
   434→   - Escuta `controllerchange` → reload da página uma vez
   435→   - Garante que usuário sempre tenha SW mais recente
   436→
   437→3. **`src/app/layout.tsx`** — adicionado `<ServiceWorkerRegister />`
   438→   no root layout (antes o componente existia mas nunca era renderizado)
   439→
   440→4. **`src/components/Header.tsx`** — adicionado `onClick={onOpenMobile}`

   659→### Bug fix during testing
   660→
   661→**Erro:** TV token não funcionava — ao acessar `/tv?key=tv_xxx` sem
   662→login, a página retornava 500.
   663→
   664→**Causa:** `SystemSetting.value` é campo `Json` no Prisma, não `String`.
   665→O `findFirst({ where: { value: token } })` falhava porque Prisma não
   666→suporta filtrar Json por string diretamente.
   667→
   668→**Solução:**
   669→1. Token agora armazenado como objeto JSON `{token: "tv_xxx"}` (não string)
   670→2. `getCompanyByTvToken` itera `findMany({ key: "tv.token" })` e faz match
   671→   em memória: `val.token === token`
   672→3. `getTvTokenAction` extrai token do JSON: `val.token` ou `val` (string)
   673→4. `regenerateTvTokenAction` faz upsert com `{token}` em vez de string
   674→
   675→### proxy.ts atualizado
